---
title: Webhook development
description: Receive real webhook deliveries from GitHub, Stripe, Slack, and others on your dev machine.
---

Webhook providers need a public HTTPS URL to deliver to. routeup gives your local
service one, so you can develop against real deliveries instead of mocking them.

## 1. Expose your local API

Run your API (say on port `8080`) and expose it:

```bash
routeup serve example-app --port 8080 --public
```

The examples below assume your saved token allows
`*.mukul.routeup.dev`.

routeup prints the local URL, public URL, exposure scope, and targets:

```txt
route: example-app
local: https://example-app.localhost
public: https://example-app.try.routeup.dev
expose: all paths
targets:
  /        http://localhost:8080

press Ctrl-C to stop
```

## 2. Point the provider at it

Register the public URL as the webhook endpoint in the provider's dashboard:

```txt
GitHub:  Settings → Webhooks → Payload URL
Stripe:  Developers → Webhooks → Add endpoint
Slack:   Your App → Event Subscriptions → Request URL
```

Use the full path your handler listens on, e.g.
`https://example-app.try.routeup.dev/api/webhooks/github`.

## 3. Watch deliveries

Tail public traffic as it arrives:

```bash
routeup logs example-app --public --follow
```

```txt
12:41:03 public example-app POST /api/webhooks/github 200 38ms req_abc123
```

Because the route and namespace are configured, you request the same endpoint on
each run instead of accepting a newly generated URL. Public claims remain subject
to the server's normal conflict rules.

## Scoping exposure

If you only want the webhook path reachable and the rest of the app private, you
can limit public exposure to a path prefix (for example `/api/webhooks/*`) so the
rest of the service stays local-only:

```json
{
  "name": "example-app",
  "port": 8080,
  "expose": {
    "paths": ["/api/webhooks/*"]
  }
}
```
